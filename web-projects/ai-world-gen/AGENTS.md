# web-projects/ai-world-gen/AGENTS.md

> **SCOPE:** files under `web-projects/ai-world-gen/`. Read `web-projects/AGENTS.md` first for the rules that cover every web-project.

## What this is

A map generator with two kinds of model and one blueprint. A text model writes a world's vocabulary once (ADR 0002); code draws the structures the vocabulary declares as rectangles with doors (`blueprint.js`); a decision model (TypeSafe's Jev) then places one cell at a time, offered only the types that fit the cell's part of the plan and its hard rules. Everything goes through OpenRouter with a key the reader pastes (ADR 0001). The `README.md` holds the concept, the roadmap with its phases, and the open questions; keep it current, because it is the memory of the project between sessions.

## Non-obvious conventions and gotchas

- **Three ways to fill the grid, one switch.** `state.models.generation` (`settings.js`, stored with the model choices) is `per-cell` (a decision per cell, `generation.js`), `whole-map` (`wholeMap.js`: one call to the narrative model for the finished grid) or `batched` (`batchedDecisions.js`: every cell as its own typed question in one decisions request). The evaluation takes the same switch as `AI_WORLD_GEN_GENERATION`. The whole-map call **turns the model's thinking off** (`WHOLE_MAP_REQUEST.reasoning`): Claude Sonnet 5 left to itself spent the whole 6,000-token budget reasoning about an 8 × 8 map and answered with an empty string. It also needs the long timeout in the same constant; the client's default is 60 s.
- **A cut-off answer is a failure.** `call` reads the body after the headers, so a slow answer aborts inside `response.json()`; it returns `{ok: false, status: 0}` with the seconds it waited, never `{ok: true, data: null}`. `generate` takes `timeoutMs` and `reasoning` for callers that need more than the default.
- **Two endpoints, two request shapes.** `decide()` posts `{model, state, questions}` to `/api/alpha/decisions` and reads `answers.<key>.{choice, confidence, probabilities}`. `generate()` posts OpenAI-shaped messages to `/api/v1/chat/completions`. Sending Jev a chat request is a 400. `models.transportFor` is the one place that tells the two kinds apart; do not branch on a model name anywhere else.
- **The decisions endpoint answers many questions in one request, up to about 65,536 input tokens.** Measured on 2026-09-22 with a real key: 128 cell questions at 60,023 input tokens are answered in 1.2 s, 160 at about 71,600 are refused with `{"error_type":"max_tokens_exceeded"}` as an HTTP 400. That 400 is not fatal and not worth retrying: `runBatchedGeneration` reads it with `isTooManyTokens`, shrinks the token budget and plans a smaller batch. `CHARS_PER_TOKEN` (2.9) is measured, not guessed; re-measure it against `usage.input_tokens` when the state changes shape.
- **A batch pays for its instructions once.** Every question in a batch carries the same instruction text, so it lives in `state.howToChoose` and each question's own `instructions` is one line. Repeating the full text per question cost 23,000 of the 56,000 input tokens an 8 x 8 map first measured, which alone decides whether a map fits in one request. Never move it back into the question.
- **The cells of one batch cannot see each other, and no state can fix that.** `neverNext`, `onlyNext`, the hard cap, `missing` and the continuation hints are all computed from the grid as it stands when the batch is built, so two cells of one batch can each take the type the other one rules out, and a "exactly one" type can land twice. This is the property the mode exists to measure; do not paper over it by shrinking batches.
- **Jev's payload was not exercised with a real key before the first deploy** (no key in the build session). `readDecisionAnswer` follows the documented System One shape. If the first real run shows a different shape, fix it there and update the README's open questions.
- **The blueprint decides the shape; the model decides the content.** `planStructures` places every `structures` entry of the vocabulary as a rectangle (a gap of one cell between rooms, at most `MAX_STRUCTURE_SHARE` of the map, one door in a wall that faces the middle, none for a `door: null` structure). `zoneAllowedTypes` then offers a wall cell its structure's wall or any `zone: "wall"` type, the door cell the door only, an interior cell its floor or any `indoor`/`any` type, and the outside any `outdoor`/`any` type, never a structure's wall or door. Seven versions without it never got doors into walls (README, version table): do not try to get rooms out of the prompt again.
- **Hard rules are typed and enforced; prose rules are advice.** Each element's `placement` (`zone`, `neverNext`, `onlyNext`, `edge`) is applied by `allowedTypes` before the question is built, and a type whose prose says "exactly one" (not "exactly one per X"; `isUniqueType`) is out once it is on the map. The excluded types go in `state.excluded` with the rule. The prose `placementRules` still go to the model as the description of each option. When you write or edit a shipped vocabulary, put the rule in both.
- **The state carries the whole map as text** (`mapSketch`: one letter per type in vocabulary order, `.` undecided, `?` this cell) plus the 8-neighbours, counts within `NEARBY_RADIUS` (2), whole-map counts, the balance sheet, `missing` (the interactable or unique types not yet on the map that this cell may hold) and the continuation hints. A 24 × 24 sketch is under 300 tokens. `cellDecision.test.js` asserts the serialised state has no `cells` key (the raw grid with probabilities never goes out).
- **The code, not the model, judges structure.** `balanceSheet` reads each type's target share from the rarity word in its placement rules (`TARGET_SHARES`; the vocabulary prompt asks for exactly those words) and lists `needed` and `overused` types. `continuationHints` names one `suggested` type only for a closable gap or a line shorter than `MAX_CONTINUED_LINE` (4), never an overused or excluded type; a cell outside next to a planned door is suggested the route type instead. v3 proved that asking the model to "continue the line" with no limit floods the map; change the limits in code and measure, do not loosen the instruction.
- **A ground type has a hard cap; a vocabulary needs a ground that is not a route.** Past `HARD_CAP_FACTOR` (2) times its target share, with three cells placed, a ground or route type is not offered while another ground type is allowed in the cell (v10). The cap cannot fire when the route is the only floor: the station's corridor and the block's street flooded until v11 gave them an open deck and a plaza. When you write a vocabulary, make the most common cell a ground and every route a line on it.
- **The map samples the probabilities.** `chooseType` with `spread` 1 draws from the returned probabilities, dropping options below `SAMPLE_FLOOR` (a third) of the best; at 8% the sample overrode the model on 27% of the cells (v4, v5). A cell records both `typeId` (what was placed) and `modelChoice` (the model's top pick), and the inspector shows both when they differ. Setting `spread` to 0 makes the loop deterministic given the model.
- **Sprite variation is a toggle, and the legend never varies.** In the pixel style a cell's variant comes from `hashCoordinate(x, y)`; with "Vary sprites" off the renderer passes seed 0, which is the variant the legend and the inspector always show. The toggle is hidden in the code styles, which have one drawing per tag. Its state lives in `settings.js`.
- **A downloaded picture is not a screenshot.** `renderMapImage` draws the whole grid into its own canvas at `DOWNLOAD_PIXELS_PER_TILE` (48, a multiple of the sheet's 12), with no camera, no frames and no corner marks. It cannot reuse `createRenderer().draw`, because `resize()` reads `clientWidth`, which is 0 on a canvas outside the page. `wholeGridImage` gives the size and the camera; `fitCamera` must not, because it clamps the scale and centres.
- **A new visual tag needs a row in two files**: `VISUAL_TAGS` in `tileset.js` (the sprite) and `STYLE_GLYPHS` in `tileStyles.js` (emoji, glyph, colour). `tileStyles.test.js` fails until both agree. Only `render.js` may call `tileFor` or `glyphFor`; `invariants.test.js` pins that.
- **The vocabulary box is the source when it is valid.** `generateWorld` in `app.js` reads the box first: valid means no model call, empty means the model writes it and the answer is written back into the box, invalid stops with the errors shown. Changing the prompt rules or the tag list can invalidate a shipped vocabulary in `presetVocabularies.js`; the tests fail, and the fix is to edit the shipped text, not the validator. A vocabulary written before `placement` and `structures` existed still validates, with an open placement and no structures: it draws no rooms.
- **A saved map file carries its plan.** `downloadMap` writes `plan` next to the grid and `loadMapFile` reads it back, so "ask again about this cell" on a loaded map still knows the cell's part. A file without a plan gets none.
- **A visual tag outside `VISUAL_TAGS` is a validation error, not a fallback**, so the model fixes it. The fallback tag `unknown` exists for cells loaded from an older file or drawn before the vocabulary is known. The sheet has four separator columns (25, 51, 77, 103); `tileset.test.js` fails on a tag placed on one.
- **Tile positions are `[column, row]`, and the pixel is `1 + index * 13`.** The sheet is 206 × 50 tiles. `tileset.test.js` reads the PNG header, so a replaced PNG with another size fails loudly.
- **`FATAL_STATUSES` (401, 402, 403, 404) stop the run at once**; 0, 429 and 5xx are retried with a growing pause and then fall back. Four fallbacks in a row also stop the run. A fallback cell has `source: "fallback"` and `error`; a hand-changed cell has `source: "hand"`. The renderer marks both with a coloured corner.
- **`app.js` never writes `innerHTML`.** Every label comes from a model. The one `innerHTML` in the project is inside `deployStamp.js`, with its own escaper. `invariants.test.js` checks it.
- **The order strategies take the placed Set, not their own progress**, so a cell decided by hand or loaded from a file is never offered again. A new strategy must visit every free cell exactly once; `orderStrategies.test.js` drains each one on a 7 × 5 grid and a 1 × 1 grid.
- **The key is remembered by default.** Unticking "Remember" forgets it in storage and keeps it in memory for the tab. `settings.js` is the only file that names `localStorage`, `urlState.js` never mentions the key, and both facts are pinned in `invariants.test.js`.
- **The model catalogue is fetched without a key** (`/api/v1/models` needs none) when the AI Setup screen opens, and `FALLBACK_CATALOGUE` fills the pickers until then. `:batch` variants and image or audio models are dropped in `readCatalogue`.
- **Prose in the prompts follows the same writing rules as the docs.** The vocabulary prompt and the per-cell instructions are read by a model, but a person edits them; keep them short and literal (Jev answers the exact question asked, and negations underperform).

## Evaluation before a change to the generation

Any change that can alter the maps (the per-cell prompt or state, the sampling, the orders, the shipped vocabularies) is measured before it ships (ADR 0005):

```bash
cd web-projects/ai-world-gen/evaluation
OPENROUTER_API_KEY=sk-or-... python evaluate.py run --version vN --description "what changed"
python evaluate.py report --version vN --against v(N-1)
```

`vN` is the next version name after the last file in `evaluation/results/`; a run with `AI_WORLD_GEN_GENERATION=whole-map` or `batched` is not a version of the loop and gets a name like `v-llm` or `v-batch`. Commit the generator change before the run: the Galtea version's description records the commit. A Galtea session stays `PENDING` until something finishes it, so `run` calls `sessions finish` (through the CLI; the SDK has no such call) right after the evaluations, with the stopping reason "the map is complete". A session left pending looks like an unfinished conversation in the dashboard. The run also draws every map to `results/vN/<case>.png` and attaches it to the Galtea output as a file part (`{"assistant_message": text, "content": [{"type": "file", "uri": "s3://...", "mimeType": "image/png"}]}`); the `s3://` form is what the API stores for its own uploads. Commit the PNGs: they are small and they are how a map is compared across versions without opening Galtea. The run is 38 maps, 3,008 decisions (about 25 cents of Jev) and under ten minutes with `--parallel 4`; the three 16 × 16 maps take most of it. Do not edit a runtime module while a run is going: every test case is its own `bun` process that loads the modules when it starts. Put the report's per-specification numbers in the pull request. A new rule is an entry in `SPECIFICATIONS` and `METRICS` (or `JUDGE_METRICS`, with its prompt) in `mapMetrics.js` with a test, a dataset in `testCases.json`, then `python evaluate.py setup` to create it in Galtea and `python evaluate.py rescore --version vN` for every past version, so the new metric has a history. Galtea takes a judge metric by **name** in `evaluations.create`, a computed one by `{id, score}`; a judge metric needs an evaluator model (`AI_WORLD_GEN_JUDGE_MODEL`, `GPT-5.2`; claude-sonnet-5 fails to answer in the expected shape). A `rescore --no-push` writes the scores locally, and a later `rescore` then sends nothing new: push in one go, or send the scores by hand. A new dataset also needs `python evaluate.py backfill --version vN` for every past version: it checks the project out at the version's commit (`git archive`, from the repository root) and draws the missing cases with that code, so every version is evaluated on the same 38 seeds. `backfill` asks for no judge evaluation; `python evaluate.py rescore --version vN --judge` adds the judge to every session of a version that has none yet (it lists each session's evaluations first, so a second run judges no map twice).

## Tests

Every module marked "Pure" has a sibling `*.test.js`, and new behaviour goes in test-first (root ADR 0012). `app.js`, `render.js` and `openRouterClient.js` have none by design; anything in them worth a test belongs in a pure module instead. `invariants.test.js` pins the decisions of the ADRs. `blueprint.test.js` runs the planner over twenty seeds and checks every rectangle; `presetVocabularies.test.js` checks that every shipped type has a placement and every structure a wall of zone `wall`.

```bash
cd web-projects/ai-world-gen && bun test
```
